Privacy and data handling — beb personal test backups

Last updated: 16 October 2026

This tool is operated by its owner for that owner's private beb test environment. This page describes the intended daily backup configuration; automation is enabled only after setup and verification.

Information used

The tool uses the connected Google account's email address to verify that backups go to the intended account. Its Drive permission is limited to files created by this app or explicitly made available to it. It reads and manages its own backup folder, encrypted backup files, verification metadata and available storage quota.

Backups contain beb test business records, including customer and booking information, payment and document metadata, settings, contracts and photos. Morning PDF previews and issued-original PDFs are excluded. Google passwords, Calendar grants and Morning API credentials are not needed by the backup runner.

Processing and storage

The owner-controlled private GitHub Actions runner reads beb-test data, encrypts the backup, uploads it to the owner's private Google Drive, downloads and decrypts a copy, and verifies it through a disposable local restore. Plaintext is temporarily present in the runner during creation and verification. It is not uploaded as a workflow artifact or placed in the code repository. Temporary files are cleaned up by the runner and the hosted runner is ephemeral.

GitHub Actions holds the test database credential, backup encryption key and Google Drive app credentials as repository secrets. People able to change the runner's code could use those secrets; repository access must remain limited to the owner. The owner keeps a separate recovery-key copy outside GitHub and Drive.

Supabase, GitHub and Google process data as needed to provide their respective services. The application does not sell backup data, use it for advertising, or send it to an AI service for model training. Google Workspace data is used only for the backup, verification, recovery and retention functions described here, in accordance with the Google API Services User Data Policy, including its Limited Use requirements.

Retention and controls

When enabled, the daily retention policy moves verified backups managed by this policy to Drive Trash only after both the backup date and file creation date are more than 365 days old. It preserves at least three verified points. Google applies its own Trash recovery and automatic-removal rules. Earlier manual backups without the daily-policy marker are not automatically removed.

The owner can stop scheduled backups in GitHub and revoke the app's Google access in Google Account settings. Revocation stops future access; it does not delete existing Drive backups. Existing backup files can be downloaded or deleted by the owner using Google Drive. Deleting the only remaining recovery key prevents decryption.

For questions or deletion assistance, contact the owner through the support email shown on the Google consent screen.

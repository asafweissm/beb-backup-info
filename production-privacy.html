Privacy and data handling — beb production backups

Last updated: 19 October 2026

This tool is operated by its owner for private beb production backups. This page describes the configured design; scheduling starts only after setup, a verified manual backup and an independent recovery-key copy.

Information used

The connected Google account's verified email identifies the intended destination. Drive permission is limited to app-created files and files the owner explicitly makes available to this app. The tool manages its own private backup folder, encrypted archives and verification metadata and checks available storage quota.

Backups contain business records, including customer and booking information, payment and document metadata, settings, contracts and photos. All Morning PDF files and their cached hashes are excluded. Google passwords, Calendar grants and Morning API credentials are not used by the backup job.

Processing and storage

A private Google Cloud Run job reads the production Supabase source, encrypts the archive, uploads it to the owner's private Google Drive, downloads and decrypts it, and checks records and file hashes through a disposable database restore. Plaintext exists temporarily inside the ephemeral job during creation and verification; it is not published as a build artifact, code or log. Temporary files are cleaned up by the runner.

The production database credential, encryption key and separate Drive OAuth grant are held in Google Secret Manager in the dedicated production backup project. Access is scoped to the backup runtime. People able to change the job's code or privileged project configuration could access these credentials, so that access must remain restricted. The owner keeps an independent recovery-key copy outside the runtime and backup folder.

Supabase and Google process data to provide these services. GitHub hosts source code and public information pages, not the running production backup job or its secrets. The tool does not sell backup data, use it for advertising, or send it to an AI service for model training. Google data is used only for backup, verification and recovery, in accordance with the Google API Services User Data Policy, including its Limited Use requirements.

Retention and controls

Automatic retention and deletion are disabled. Backup archives remain until the owner removes them or separately authorizes a retention policy. The owner can stop Cloud Scheduler or disable the backup job, and revoke this app's access in Google Account settings. Revocation stops future access without deleting existing archives. The owner can download or delete files through Google Drive; losing every recovery-key copy prevents decryption.

Backup health is shown inside beb. No external backup monitoring or email reporting is configured by this tool; Google may send its own billing or service notices.

Questions or deletion requests can be directed to the owner using the support email displayed on the Google consent screen.
